# dotfiles

Personal Fedora Workstation setup. Goal: if this machine dies or I want to
start fresh, `git clone` + `./bootstrap.sh` gets me back to where I am today.

## Layout

```
.
├── bootstrap.sh        # single entrypoint, idempotent, run this
├── packages.txt         # dnf package names, one per line
├── copr.txt             # copr repos to enable before installing packages
├── gnome-settings.sh    # gsettings tweaks that don't live in a dotfile
└── home/                # mirrors $HOME; bootstrap.sh symlinks these into place
    ├── .zshrc
    └── .config/
        ├── helix/config.toml
        └── ghostty/config.ghostty
```

Anything under `home/` is symlinked to the same relative path under `$HOME`,
so editing a file here edits your live config too - no separate "apply" step
for dotfile changes, only `bootstrap.sh` needs re-running when packages or
system settings change.

## Fresh machine

```sh
sudo dnf install -y git
git clone <this-repo-url> ~/Code/dotfiles
cd ~/Code/dotfiles
./bootstrap.sh
```

## Adding something new

- New CLI package: add it to `packages.txt` (and `copr.txt` if it needs a
  COPR repo first), re-run `./bootstrap.sh`.
- New dotfile: put it under `home/` at the path it should occupy relative to
  `$HOME`, re-run `./bootstrap.sh` (or just `ln -s` it yourself, bootstrap
  will pick up existing symlinks fine next time).
- New GNOME/gsettings tweak: add the `gsettings set ...` line to
  `gnome-settings.sh`.

## Not tracked here (on purpose)

- `mimeapps.list` / `xdg-terminals.list` - regenerated by the desktop as apps
  get installed, not meaningful to hand-manage.
- Anything containing secrets (SSH keys, API tokens, etc.) - never goes in
  this repo.
